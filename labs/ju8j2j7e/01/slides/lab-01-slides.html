LAB 01: First Commit, First Push

You have something worth saving. Today you save it properly.

First lab of the term, so a chunk of this hour is about the room settling rather than git. Start on time anyway.

What You Are Doing Today

  • Tell git which files to ignore, with a .gitignore
  • Turn the project folder into a repository
  • Stage and commit everything, once
  • Create a public GitHub repo and push to it, in one command
  • Confirm it landed, then submit github.json to Gradescope

The full instructions are in Canvas, under Lab 01. This is the shape, not the detail.

Five things, and they are in a strict order: each one fails confusingly if the one before it was skipped. The whole lab is maybe fifteen minutes of typing for someone whose environment works. Budget the rest for the environment, authentication, and the people who have not started.

Work in 2s and 3s

Find one or two other people and work together. Threes are fine, and on an odd day they are expected.

Everyone submits their own work. Working together means talking through what a command actually did, not one person typing while the others watch.

Say this out loud rather than pointing at the slide. Students default to working alone in lab because it feels like homework. Watch for the group where one person drives the whole hour. Ask the quiet one to explain what just happened, kindly. If they cannot, that group needs to slow down, not speed up.

Start with .gitignore


node_modules/
.env
github.json

Before git init, not after. Untracking something later is much more work than never tracking it.

The single most common way this lab goes wrong: committing node_modules. It is thousands of files, the push takes forever, and unpicking it is a genuinely hard git exercise that is not what today is about. If someone has already done it, the fastest fix is to delete the .git directory and start the lab again. Say that plainly rather than teaching git rm --cached to a student on their first day of version control.

init, then look before you commit


git init
git status

Expect server.js and package.json under untracked files. Not node_modules/. If you see it, the .gitignore is wrong or in the wrong folder.

Make them actually run git status and read it. This is the checkpoint that catches the .gitignore mistake before it becomes a commit. Common cause when node_modules still shows: the .gitignore was saved in the parent folder, or saved as gitignore.txt by an editor on Windows.

Stage and commit


git add .
git commit -m "initial Express server with two routes"
If git refuses with a message about identity, they never set user.name and user.email. That is on the Installing Git page in Canvas, and it matters beyond today: commits stamped with the wrong address do not count as their work when sprints are graded.

Create the repo and push


gh repo create web-server --public \
  --source=. --remote=origin --push

One command. It makes the GitHub repository, wires it up as origin, and pushes.

This is where authentication bites. If gh is not logged in, gh auth login and follow the browser prompts. Have them run gh auth status first if you suspect it. Anyone working outside the container needs the GitHub CLI installed, or they can create the repo in the browser and push with plain git remote add and git push. Either is fine today.

Confirm, then submit


git log --oneline
gh browse

Then make github.json with your repository URL and upload it to Gradescope.

Do not let anyone leave on 'it pushed'. Make them open gh browse and see server.js on the page. A push that went to the wrong place looks identical from the terminal. Then check they actually submitted to Gradescope. Every term, people finish the work and forget the submission.

Before You Leave

  • Your repo opens in the browser and server.js is visible on the page
  • git log shows your commit
  • github.json is uploaded to Gradescope
  • The lab exit ticket is submitted, with today's word
Run this list out loud in the last ten minutes. The Gradescope upload is the one people miss, because the work feels finished once GitHub shows the code. Anyone who is not going to finish: tell them it is due tonight, point them at office hours, and make sure they leave knowing exactly which step they are stuck on.
