LAB 01: First Commit, First Push

You have something worth saving. Today you save it properly.

First lab of the term, so a chunk of this hour is about the room settling rather than git. Start on time anyway.

What This Lab Is About

You already have an Express server that runs. Today you put it under version control and get it onto GitHub properly: ignore what should not be tracked, make one real commit, and push it to a repository of your own.

This is the same sequence every sprint and the whole team project runs through. Nothing about it gets more complicated later. There is just more of it.

The steps are in Canvas, under Lab 01. Work from there, not from the screen.

This slide is the whole explanation. Do not walk the steps from the front; they are written properly in Canvas and reading them aloud just delays people starting. WHAT THE HOUR ACTUALLY IS, for you rather than the room: write a .gitignore, git init, one commit, then gh repo create with --source=. --remote=origin --push, then confirm and submit github.json to Gradescope. Fifteen minutes of typing for someone whose environment works. Budget the rest for the environment and for people who have not started. THE FOUR THINGS THAT ACTUALLY GO WRONG, in the order you will meet them: 1. COMMITTING node_modules. By far the most common. Thousands of files, a very slow push, and unpicking it is a hard git exercise that is not what today is about. The fastest fix is to delete the .git directory and start the lab again; say that plainly rather than teaching git rm --cached to someone on their first day of version control. The cause is nearly always a .gitignore written after git init, saved in the parent folder, or saved as gitignore.txt by an editor. 2. SKIPPING git status. It is the checkpoint that catches the above before it becomes a commit. Make people actually run it and read the output. 3. NO GIT IDENTITY. If git refuses with a message about identity, they never set user.name and user.email. That is on the Installing Git page, and it matters beyond today: commits stamped with an address GitHub does not recognise do not count as their work when sprints are graded. 4. gh NOT AUTHENTICATED. gh auth status first if you suspect it, then gh auth login and follow the browser prompts. Anyone working outside the container may not have the GitHub CLI at all; creating the repo in the browser and pushing with git remote add plus git push is completely fine today.

Work in 2s and 3s

Find one or two other people and work together. Threes are fine.

Everyone submits their own work. Working together means talking through what a command actually did, not one person typing while the others watch.

Say this out loud rather than pointing at the slide. Students default to working alone in lab because it feels like homework. Watch for the group where one person drives the whole hour. Ask the quiet one to explain what just happened, kindly. If they cannot, that group needs to slow down, not speed up.

Container Still Not Working?

Put your hand up now. That is what we are here for, and several of you are in the same position.

But if it is going to take a while, get the lab done first. You can install Node and Git directly on your machine, and both are written up in Canvas. Finish the lab, then we fix the container with whatever time is left.

This is the slide that matters most today. Roughly a quarter of the room could not get a route running on Tuesday because of the container, and the lab is due tonight. The order of operations is deliberate: unblock them for the lab first, fix the container second. A student who leaves with a working container and an unsubmitted lab has had a worse morning than one who leaves with the reverse. The two pages are "Installing Node.js Locally" and "Installing Git Locally", both in Canvas. Git is the one that matters for this lab. If you cannot sort someone's container out, do not sink the hour into it. Send them to message Tim through the Canvas Inbox and he will find a time to sit down with them. If more than a handful are stuck on the same thing, do it as a group at the front rather than one laptop at a time.
