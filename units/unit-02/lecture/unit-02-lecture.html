Why split routes into files at all?

"I get that it helps organize routes, but I'm still confused why we need to split them into separate files instead of keeping them all in server.js."


app.use('/', pagesRouter);
app.use('/api', apiRouter);

The prefix is the point


// routes/api.js
router.get('/info', ...)   // the file says /info

// server.js
app.use('/api', apiRouter)
// the browser sees /api/info

One of you hit exactly this: /api/status worked and /status said no path found. The router file never knows its own prefix.

params or query?

Path parameter. Part of the address. No route without it. /hello/:name

Query parameter. Optional extra. The route matches with or without it. /count?from=1


req.query.from || 1   // always needs a fallback
req.params.name       // guaranteed to exist

And what is curl?

A web browser with no window. You give it a URL, it makes the request, it prints what came back.


curl -i http://localhost:3000/hello/Alice


HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

Hello, Alice!

Already installed, in the container and on your machine. Full page in Canvas: 🧩 curl.

res.status() does not stop your function

"It looks like it should end the request like a return statement in a normal function, but it doesn't."


if (!thing) {
  // note the return
  return res.status(404).send('Not found');
}
res.json(thing);

Without the return


if (!thing) {
  res.status(404).send('Not found');
}
res.json(thing);   // runs anyway

The browser still shows 404 Not found, so from the outside it looks like it worked. The damage is on the server:


Error [ERR_HTTP_HEADERS_SENT]: Cannot set
headers after they are sent to the client

When two routes overlap

"What route gets chosen if there is an overlap, is it always the first one?"


app.get('/repeat/hello', ...)   // checked first
app.get('/repeat/:word', ...)   // catches everything else

Yes. First match wins, in registration order. Same rule as Tuesday.

Where does req.params.name get its name?

"Would it depend on the app.get line? If it read /hello/:nname, would the parameters now match?"


// the route declaration names the key
app.get('/hello/:name', ...)

// so this is the one that exists
req.params.name

Yes. The route declaration decides. If it said :nname, then req.params.nname would be right, which is exactly why the question called it a typo.

req.params vs req.query

One is part of the path. One is optional.


app.get('/hello/:name', (req, res) => {
  res.send(`Hello, ${req.params.name}!`);
});

app.get('/count', (req, res) => {
  const from = req.query.from;
  const to = req.query.to;
});

Fallback values with ||

A query string can always be missing.


const from = req.query.from || 1;
const to = req.query.to || 10;

Choosing what to send back

Plain text: res.send(...)

Structured data: res.json({...})

An explicit failure: res.status(400).send('Bad request')
