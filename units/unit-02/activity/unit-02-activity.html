Unit 02 activity

Filtering with Query Strings

Pairs40 minutesNot graded

Add a /projects route to the portfolio server from last class. It reads a ?tag query parameter and returns only the projects that match.

The decision you have to make

What happens when ?tag is missing entirely: show everything, or require it? What happens when it is given but matches nothing you have: an empty list, or a message saying so? Neither has a single right answer.

Real APIs disagree about this constantly. Decide as a pair, and be able to say why.

AI use on this activity: Level 1

You may ask an AI tool general questions about JavaScript, Express, or HTTP. It may not see your code, your terminal output, or the assignment text, and it may never tell you what to write.

Deciding what a missing or invalid parameter should do is the actual skill this activity builds. A tool answering it for you skips exactly that. Level 1 is the same level every Lab in this course uses, for the same reason: this is foundational skill-building, not shipped work.

How to work

  • Driver types. Navigator reads, questions, and looks things up.
  • Swap at the midpoint, but only when I tell you to. Do not swap on your own clock. Both of you write real code; whoever only watched cannot do the homework, so the swap is enforced from the front of the room, not left to pairs to remember.
  • One machine is fine. Two is fine. Talking is the part that matters.

Starting point

Start from last class's portfolio server (or a fresh one, same shape). Add a hardcoded list of three or four projects, each with a name and a tag:

const projects = [
  { name: 'Weather app', tag: 'javascript' },
  { name: 'Portfolio site', tag: 'express' },
  { name: 'Budget tracker', tag: 'python' },
];

Then the route:

app.get('/projects', (req, res) => {
  const tag = req.query.tag;
  // filter `projects` here, based on your decision above
});

Restart with npm start after every change, and check /projects, /projects?tag=express, and /projects?tag=nothing-real all three.

The thing that will get you

req.query.tag is undefined, not an error, when the parameter is missing. No crash, no warning. Test the missing case explicitly, do not assume you would notice.

Done when

  1. The /projects route filters correctly by ?tag when a real one is given.
  2. You can state your two decisions (missing tag, no-match tag) and why you made each one.
  3. You have compared your answer with a neighbouring pair, but only once I say it is time; that comparison is its own short phase, not something to rush into once your code works.

You will need this for your exit ticket

Before you leave, you will be asked to name one route you personally wrote and one route your partner wrote. Keep track as you go, driver and navigator both, so you are not reconstructing it from memory at the door.

If you finish early

Add a second, different query parameter to the same route, for example ?sort=name, and make the same kind of decision: what happens when it is missing, or set to something that is not a valid sort option?
