What curl actually is

Nine of you asked. It is a client that prints instead of rendering.


curl -X POST localhost:3000/entries \
  -H "Content-Type: application/json" \
  -d '{"title":"From curl","body":"Hello"}'

{"id":4,"title":"From curl","body":"Hello"}

The browser sends a request and draws the answer. curl sends the same request and prints the answer. That printed line is the response body.

JSON is text. An object is not.

Seven asked what actually changes on the round trip. Run this one live.


const before = { title: "a", when: new Date(),
                 draft: undefined, score: NaN };

JSON.parse(JSON.stringify(before));

// title: "a"
// when:  "2026-09-22T12:00:00.000Z"  (was a Date)
// score: null                        (was NaN)
// draft: gone

The Date came back a string. draft vanished. NaN became null. Six types survive, and anything else is converted or dropped.

express.json() and res.json() are opposites

Same word, opposite directions. This was asked outright.


app.use(express.json());   // INCOMING: text -> req.body

res.json({ id: 4 });       // OUTGOING: object -> text

One parses the request on the way in. The other serialises your answer on the way out. Neither one knows about the other.
