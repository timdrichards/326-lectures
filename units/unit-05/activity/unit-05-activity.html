Unit 05 activity

Creating Something New

Pairs40 minutesNot graded

Add a POST route for one small resource of your own choosing, not entries, reading two fields from req.body, pushing to an array, and responding 201 with the created object.

The decision you have to make

What happens if a required field is missing from the request body? Reject with 400 and a real error message, or silently create the entry with an empty or default value?

There is no single right answer. Some real APIs are strict, some are permissive. Decide, and be able to defend it.

AI use on this activity: Level 1

You may ask an AI tool general questions about JavaScript, Express, or HTTP. It may not see your code, your terminal output, or the assignment text, and it may never tell you what to write.

Whether an API should be strict or permissive about missing input is a real design trade-off with working examples on both sides in production software. Deciding it, not looking up which one is 'correct', is the point. Level 1 is the same level every Lab in this course uses, for the same reason: this is foundational skill-building, not shipped work.

How to work

  • Driver types. Navigator reads, questions, and looks things up.
  • Swap at the midpoint, but only when I tell you to. Do not swap on your own clock. Both of you write real code; whoever only watched cannot do the homework, so the swap is enforced from the front of the room, not left to pairs to remember.
  • One machine is fine. Two is fine. Talking is the part that matters.

Starting point

Start from last class's server. Add the middleware and a route:

app.use(express.json());

const wishlist = [];

app.post('/wishlist', (req, res) => {
  const { item, note } = req.body;
  // your decision goes here
  const newItem = { item, note };
  wishlist.push(newItem);
  res.status(201).json(newItem);
});

Test with curl:

curl -X POST http://localhost:3000/wishlist \
  -H "Content-Type: application/json" \
  -d '{"item": "headphones"}'

The thing that will get you

Forgetting express.json() makes req.body undefined, and destructuring a field out of undefined crashes the route immediately, a real 500 error. If your route breaks on the first real request, this is the first thing to check.

Done when

  1. A real POST request creates a new item and gets a 201 back with the created object.
  2. You have actually tested the missing-field case, not just decided what it should do.
  3. You have compared your answer with a neighbouring pair, but only once I say it is time; that comparison is its own short phase, not something to rush into once your code works.

You will need this for your exit ticket

Before you leave, you will be asked to name one field or route you personally wrote and one thing your partner wrote. Keep track as you go, driver and navigator both, so you are not reconstructing it from memory at the door.

If you finish early

Restart your server after a successful POST and confirm the entry is really gone, then write one sentence explaining, in your own words, why. Then look at the unit's own Home Exercise (a DELETE route) and add it to your own resource.
