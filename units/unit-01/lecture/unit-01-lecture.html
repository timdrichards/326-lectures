Routes are tried in order

"I thought the server would figure out which route made the most sense. It just checks top to bottom?"


app.get('/hello', ...)   // checked first
app.get('/:name', ...)   // never reached for /hello

// swap them and /hello is swallowed by /:name

First match wins. Not best match. Specific routes go above general ones.

app.get vs app.use


// one method, one exact path
app.get('/path', handler)

// every method, every path, in order
app.use(handler)

One of you had it already: get is a logic gate for a specific URL, use is the everything-else catch. That is why the 404 handler is last.

Why a route can go missing


// a catch-all matches everything
app.use((req, res) => res.status(404)...);

// so this is never reached
app.get('/status', ...);

One of you hit this and worked it out alone. The catch-all matches everything, so anything below it is dead. app.listen conventionally goes last, but a route after it still works: position relative to the other routes is what matters.

A route is a handler you register

Nothing runs until a request arrives.


app.get('/', (req, res) => {
  res.send('Hello, web!');
});

app.listen(3000);

Running it

Start: npm start

The terminal does not come back. That is correct: the process is alive, waiting for requests.

Stop: Ctrl+C

After any edit: stop it and run npm start again. Node read your file once, at startup.

What package.json is

The manifest for your project.


{
  "name": "unit-01",
  "type": "module",
  "scripts": {
    "start": "node server.js"
  },
  "dependencies": {
    "express": "^4.18.2"
  }
}

npm install reads dependencies and fetches what is listed."type": "module" is what lets you write import instead of require. npm start runs whatever scripts.start says, here just node server.js.
