Unit 01 activity

Route Design Challenge

Pairs40 minutesNot graded

Build a small Express server for a personal portfolio site. Three or four routes, each returning a short line of text. You are not building a real portfolio; you are deciding what its URLs should be.

The decision you have to make

What pages does a portfolio actually need, and what URL should each one live at? You will disagree about at least one. That disagreement is the activity.

Should "About Me" be /about, /about-me, or /aboutme? There is no answer key. Be able to say why yours.

AI use on this activity: Level 1

You may ask an AI tool general questions about JavaScript, Express, or HTTP. It may not see your code, your terminal output, or the assignment text, and it may never tell you what to write.

The naming decision is the entire point of this exercise. Having a tool make it for you does not save time here, it deletes the activity. Level 1 is the same level every Lab in this course uses, for the same reason: this is foundational skill-building, not shipped work.

How to work

  • Driver types. Navigator reads, questions, and looks things up.
  • Swap at the midpoint, but only when I tell you to. Do not swap on your own clock. Both of you write real code; whoever only watched cannot do the homework, so the swap is enforced from the front of the room, not left to pairs to remember.
  • One machine is fine. Two is fine. Talking is the part that matters.

Starting point

Create a folder, then:

npm init -y
npm install express

Open the package.json that npm init wrote and add two things: "type": "module", so import works, and a start script, so you never have to type node by hand.

{
  "name": "portfolio",
  "type": "module",
  "scripts": {
    "start": "node server.js"
  },
  "dependencies": {
    "express": "^4.18.2"
  }
}

Then server.js:

import express from 'express';

const app = express();
const PORT = 3000;

app.get('/', (req, res) => {
  res.send('Hello, web!');
});

app.listen(PORT, () => {
  console.log(`Listening on http://localhost:${PORT}`);
});

Run it with npm start and open http://localhost:3000. Add your routes above app.listen.

The two things that will get you

The terminal does not come back. That is correct. The server is running. Ctrl+C stops it.

Your edit did nothing. Node read the file once, at startup. Stop the server and start it again with npm start after every change.

Done when

  1. Three or four routes work in the browser, and both of you wrote some.
  2. You can name one route you disagreed about, and say why you chose what you chose.
  3. You have compared your answer with a neighbouring pair, but only once I say it is time; that comparison is its own short phase, not something to rush into once your code works.

You will need this for your exit ticket

Before you leave, you will be asked to name one route you personally wrote and one route your partner wrote. Keep track as you go, driver and navigator both, so you are not reconstructing it from memory at the door.

If you finish early

First, take the naming you rejected and make the strongest case you can for it. If that case is easy to make, your original choice may have been habit rather than reasoning.

Once you have genuinely done that, here is real work to extend into, all of it built from what Unit 01's own page already covers:

  • More routes. A portfolio site plausibly wants a /projects or /contact page too. Keep applying the same naming discipline, not just adding pages for the sake of it.
  • A piece of logic, not just a string. The unit's Real World section covers a PORT read from process.env and a catch-all 404 handler registered with app.use(), no path, last. Add one of those for real.
  • A JSON route. The unit's Home Exercise builds a GET /status route returning res.json() instead of res.send(). Try the same idea here: a route that returns structured data about the site itself, not just text.
