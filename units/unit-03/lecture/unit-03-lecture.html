From text to HTML

A real file off disk, not a string that happens to arrive as text/html.


app.get('/', (req, res) => {
  const dir = join(import.meta.dirname, 'public');
  res.sendFile(join(dir, 'index.html'));
});

Static files

One line serves a whole directory, so you stop writing a route per file.


app.use(express.static('public'));

public/style.css is served at /style.css. public/index.html answers both /index.html and /.

Semantic HTML

Tags carry meaning. Use the one that says what the thing is.


<header> <nav> <main> <article> <footer>

These change nothing about how the page looks by default. That is the point: the meaning is for the browser, assistive technology and search, not for the eye.

Why templates?

sendFile sends a fixed file. Every visitor gets the same page.

That is exactly right for a stylesheet or a logo, and exactly wrong for a list of entries that changes every time someone adds one.

A template is HTML with placeholders. The file on disk never changes. The output changes with every request.

Setting up EJS

Two lines of configuration, then render by name.


app.set('view engine', 'ejs');
app.set('views', 'views');

res.render('entries', { title, entries });

Template syntax


<%= value %>   prints it, HTML-escaped
<% code %>     runs it, prints nothing
<%- value %>   prints it raw, no escaping

Escaped shows the tags as text. Raw lets the browser run them. The browser cannot tell your markup from a visitor's, so escaping is what keeps their words as words instead of part of your page.


title = '<b>Notes</b>'
<%= title %>   page shows   <b>Notes</b>
<%- title %>   page shows   Notes, in bold

Partials

A fragment you include, so the nav lives in one file instead of five.


<%- include('partials/header') %>

Raw output, deliberately. The partial is markup you wrote, not input from a user.

How express.static Picks a File

Three of you asked how Express knows which file to send.


app.use(express.static('public'));

GET /style.css   ->  public/style.css
GET /logo.png    ->  public/logo.png
GET /            ->  public/index.html

It maps the URL path straight onto a filename inside that folder. No file matches? Express moves on and your routes run.

You Found a Real Bug

The Real World section shows a template and then never uses it.


// it shows views/entries.ejs ... then ignores it
const inner = '<ul>' + entries.map(
  e => `<li>${e.title}</li>`).join('') + '</ul>';
res.render('layout', { title, body: inner, entries });

Two things wrong: the template is dead, and ${e.title} is unescaped, the exact hazard we just covered. entries is passed and never used.

Layout, Partial, or Page?

Several of you lost track of which .ejs file does what.

Page is what the route names: res.render('entries') finds views/entries.ejs.

Partial is a fragment pulled into another file with include. The header is one.

Layout is just a page that happens to wrap the others. EJS has no built-in layout; it is a convention, not a feature.

res.render() sends data, not just a file

A template plus data becomes a real page.


app.get('/entries', (req, res) => {
  res.render('entries', { entries });
});

Two EJS tags, two jobs

<%= value %> prints something.

<% code %> runs something, prints nothing.


<ul>
<% entries.forEach(entry => { %>
  <li><%= entry.title %></li>
<% }); %>
</ul>

One layout, every page

views/layout.ejs holds the shared doctype, head, header, and footer. Each page supplies only what goes inside.


<main>
  <%- body %>
</main>


res.render('layout', { title: 'Entries', body: inner });
