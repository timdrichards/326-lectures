What the Reading Check Showed

  • What res.render() can do that res.sendFile() cannot: send real server data into the page, not just a file
  • Which EJS tag runs real JavaScript, a loop or an if, without printing anything itself

res.render() sends data, not just a file

A template plus data becomes a real page.


app.get('/entries', (req, res) => {
  res.render('entries', { entries });
});

Two EJS tags, two jobs

<%= value %> prints something.

<% code %> runs something, prints nothing.


<ul>
<% entries.forEach(entry => { %>
  <li><%= entry.title %></li>
<% }); %>
</ul>

One layout, every page

views/layout.ejs holds the shared doctype, head, header, and footer. Each page supplies only what goes inside.


<main>
  <%- body %>
</main>


res.render('layout', { title: 'Entries', body: inner });

Activity: Handling the Empty State

Build views/events.ejs that renders a hardcoded list of three or four events, each with a title, from an events array.

Decide together: what should the page show when events is empty? Nothing at all, a friendly message, or something else? Build it for real with an <% if %> block, do not just imagine it.
