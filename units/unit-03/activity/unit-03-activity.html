Unit 03 activity

Handling the Empty State

Pairs40 minutesNot graded

Build views/events.ejs that renders a hardcoded list of three or four events, each with just a title.

The decision you have to make

What should the page show when the events array is empty: nothing at all, a friendly message, or something else? Build it for real with an <% if %> block; do not just imagine it.

Try it: temporarily set your array to [] and look at what your own page actually does before deciding it needs fixing.

AI use on this activity: Level 1

You may ask an AI tool general questions about JavaScript, Express, or HTTP. It may not see your code, your terminal output, or the assignment text, and it may never tell you what to write.

What the empty state should say is a design decision about a real person reading the page, not a syntax question. An AI can explain EJS tags; it should not choose your message. Level 1 is the same level every Lab in this course uses, for the same reason: this is foundational skill-building, not shipped work.

How to work

  • Driver types. Navigator reads, questions, and looks things up.
  • Swap at the midpoint, but only when I tell you to. Do not swap on your own clock. Both of you write real code; whoever only watched cannot do the homework, so the swap is enforced from the front of the room, not left to pairs to remember.
  • One machine is fine. Two is fine. Talking is the part that matters.

Starting point

Start from last class's server. Add the route and a hardcoded array:

const events = [
  { title: 'Career fair' },
  { title: 'Hackathon kickoff' },
];

app.get('/events', (req, res) => {
  res.render('events', { events });
});

Then views/events.ejs:

<ul>
<% events.forEach(event => { %>
  <li><%= event.title %></li>
<% }); %>
</ul>

Restart with npm start after every change.

The thing that will get you

A missing semicolon or brace inside <% %> crashes the whole page, not just the list, with a stack trace in the terminal naming the exact template line. Read that line before guessing.

Done when

  1. The events list renders correctly with real data in the array.
  2. You have actually tested the empty case, not just decided what it should do.
  3. You have compared your answer with a neighbouring pair, but only once I say it is time; that comparison is its own short phase, not something to rush into once your code works.

You will need this for your exit ticket

Before you leave, you will be asked to name one part of today's template you personally wrote and one part your partner wrote. Keep track as you go, driver and navigator both, so you are not reconstructing it from memory at the door.

If you finish early

Add a second field to each event, for example a date, and show it too. Then decide: should events with no date sort to the top, the bottom, or somewhere in between? You do not need to write real sorting logic if you do not want to, deciding the answer and saying why counts.
